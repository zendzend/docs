Workflows are visual automations you build on a canvas. Each workflow has a **trigger** that starts it and one or more **steps** that run in order. Use them to take a piece of media through a repeatable chain of work — for example encode a video, generate captions for it, publish it to YouTube, and announce it in Slack — without doing each step by hand.

Find them under **Automations → Workflows** in the sidebar.

<Info>
  Workflows are related to but separate from [Rules](/automation/rules). A rule reacts to a live production or device event and runs actions on your gear through an on‑prem [agent](/automation/agents). A workflow is a multi‑step chain that works on your media, and it can be started by a rule.
</Info>

## Build a workflow

<Steps>
  <Step title="Create the workflow">
    On the **Workflows** page, click the **New workflow** button, give it a name, and open it to reach the canvas.
  </Step>
  <Step title="Set how it starts">
    Configure the trigger to choose how the workflow is started — by hand, by a rule, or from a video in the media library. See [How a workflow starts](#how-a-workflow-starts).
  </Step>
  <Step title="Add steps">
    Add one or more steps from the palette and arrange them in the order they should run. See [The steps you can add](#the-steps-you-can-add).
  </Step>
  <Step title="Configure each step">
    Open a step to fill in its settings. Steps that talk to an outside service — Publish to YouTube, Slack message, Ask Claude, Ask ChatGPT — use one of your [connected accounts](/automation/overview), and the Encode step uses your encoding account's configurations.
  </Step>
  <Step title="Run it">
    Start the workflow with the **Run** button, or let its trigger start it. Each run appears in the run history so you can follow its progress.
  </Step>
</Steps>

## The steps you can add

| Step | What it does |
| --- | --- |
| Encode | Encode the video with your encoding account's configurations. |
| Generate captions | Transcribe the video and attach subtitles to it. |
| Publish to YouTube | Upload the finished media to YouTube. |
| In-app notification | Send a completion toast to your team. |
| Webhook | POST the result to a URL you set. |
| Slack message | Post a message to a Slack channel. |
| Ask Claude | Ask Claude something and write the answer into a field. |
| Ask ChatGPT | Ask ChatGPT something and write the answer into a field. |

The steps that work on the media — Encode, Generate captions, Publish to YouTube — expect the run to have a video to act on, so give the workflow a video subject when you start it.

## How a workflow starts

A workflow's trigger decides where it can be started from:

- **By hand or by a rule** — start it with the **Run** button in the editor, or have a [rule](/automation/rules) start it when a production event occurs.
- **From a video in the media library** — Fabl also offers the workflow on every video in your media library, and runs it with that video as its subject.

## How steps pass work along

Steps run in the order you arrange them, and a later step reads what an earlier step wrote **in the same run**. For example, an **Ask Claude** step can write a summary into a field, and a **Slack message** or **Publish to YouTube** step further down the chain that reads that same field goes out carrying the answer the model just wrote.

<Note>
  Every field a workflow reads is checked when the run starts: a workflow that names a field nothing carries is refused before any step runs, so a setup mistake is caught up front rather than part‑way through.
</Note>

## Watch and manage runs

Each time a workflow runs it appears in the run list on the **Workflows** page. A run is in one of four states:

| Status | Meaning |
| --- | --- |
| Running | The run is still working through its steps. |
| Completed | Every step finished. |
| Failed | A step could not complete; open the run to see which one and why. |
| Cancelled | The run was stopped before it finished. |

Open a run to see each step's outcome. From the run you can:

- **Stop** a run that is still running.
- **Delete** a finished run from the history.

To run a workflow again, start it again — open it and use **Run**, or start it from its video in the media library. There is no re‑run button on a past run.

<Tip>
  Try a new workflow on a spare or test video before pointing it at live media. Confirm that encodes, captions, and publishes land where you expect, and that any Slack or YouTube step posts to the right place, before you rely on it.
</Tip>
