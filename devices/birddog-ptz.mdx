The **BirdDog PTZ** device controls BirdDog cameras. Motion and presets go over VISCA, while NDI settings, tally and picture controls go over the camera's REST API, so one device covers both halves.

## Connection

Provide the camera's **host**, its **REST port** and its **VISCA-over-IP port**, and the **VISCA camera address**. Leave **Model** blank to have the family detected.

## Commands

### Movement and presets

| Command | What it does |
| --- | --- |
| Drive | Moves the head in one of eight directions at a pan and tilt speed |
| Stop | Stops pan and tilt movement |
| Go to position | Moves to an absolute pan/tilt position, where 0 is centre |
| Recall preset | Recalls a stored preset |
| Power | Powers the camera on or puts it into standby |

### NDI and tally

| Command | What it does |
| --- | --- |
| Set tally | Turns the onboard tally lamp on or off |
| Set NDI mode | Encode transmits the camera as an NDI source; decode stops it |
| Set NDI pipeline | Switches between normal and low-latency mode |
| Use discovery server | Enables or disables the configured NDI discovery server |

### Picture

| Command | What it does |
| --- | --- |
| Exposure mode | Sets the exposure mode |
| Backlight compensation | Turns backlight compensation on or off |
| White balance | Sets the white-balance mode |

Steps a model does not support are rejected by the camera rather than silently ignored. A raw REST command covers the rest, such as gain, shutter, encode bandwidth and audio.

## Triggers

Rules can react to the connection changing, the tally changing, the NDI mode changing, the power state changing, and a preset being recalled.

## State

The device reports its connection state, the NDI source name, tally and power state, and the last recalled preset.
